# Приложение TargetVPN (Android)

Клиент, который привязывает подписку к конкретному телефону по HWID.
Пользователь вводит код из мини-аппа один раз, дальше приложение само проверяет
подписку и получает актуальный ключ подключения.

## Как работает привязка

1. В мини-аппе пользователь жмёт «Показать код привязки» — сервер выдаёт
   одноразовый код на 15 минут.
2. Приложение отправляет код вместе с HWID: SHA-256 от `ANDROID_ID` и
   характеристик сборки. Само значение никуда не уходит, на сервере лежит хеш.
3. В ответ приходит постоянный токен. Дальше каждый запрос идёт с токеном и
   заголовком `X-HWID` — сервер сверяет их между собой.
4. Токен, скопированный на другой телефон, не работает: HWID не совпадёт,
   сервер ответит 401, приложение вернётся к экрану ввода кода.
5. Отвязка платная (по умолчанию 50 ₽, цена меняется в админке). После оплаты
   HWID и токен обнуляются, и приложение можно привязать к новому телефону.
   Администратор может отвязать бесплатно из карточки пользователя.

## Сборка

Локально:

```bash
cd targetvpn/android
gradle assembleDebug -PapiBase=https://ваш-домен
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Адрес бэкенда зашивается в сборку (`BuildConfig.API_BASE`), поэтому под каждый
домен нужна своя сборка.

Через GitHub Actions: вкладка Actions → **Build TargetVPN APK** → Run workflow,
указать `api_base` и версию. APK появится в артефактах сборки.

Готовый файл выложите куда угодно (например, в канал или на сам сервер) и
пропишите ссылку в админке Mini App → Настройки → «Ссылка на APK». После этого
кнопка скачивания появится у пользователей.

## Подключение

Приложение поднимает туннель само, сторонний клиент не нужен.

Внутри APK лежит `targetcore.aar` — библиотека, собранная gomobile из двух
частей: ядра **Xray** (протокол VLESS + Reality) и **tun2socks**, который
заворачивает трафик TUN-интерфейса в локальный вход ядра. Схема работы:

1. `TargetVpnService` (наследник `VpnService`) поднимает TUN: адрес 10.10.10.1,
   маршрут 0.0.0.0/0, DNS 1.1.1.1 и 8.8.8.8, MTU 1500.
2. Само приложение исключается из туннеля (`addDisallowedApplication`) — иначе
   соединение ядра с сервером ушло бы в собственный туннель и получилась бы петля.
3. Дескриптор TUN отдаётся в `Targetcore.start(fd, config, mtu)`: ядро стартует
   с конфигурацией, собранной из ссылки `vless://`, и tun2socks соединяет TUN с
   его входом SOCKS на 127.0.0.1:10808.
4. В шторке висит уведомление с кнопкой «Отключиться».

Из-за ядра APK весит около 42 МБ на архитектуру, поэтому сборка разделена:
отдельные файлы под arm64-v8a и armeabi-v7a.

### Пересборка ядра

```bash
cd core                     # модуль targetcore
gomobile bind -target=android/arm64,android/arm -androidapi 24 \
  -ldflags "-s -w" -o ../android/app/libs/targetcore.aar .
```

Нужны Go 1.22+, Android NDK и `gomobile init`.

## Версии

**2.1.0**
- DNS уходит во встроенный резолвер ядра (правило на порт 53 и выход
  `dns-out`), а не полагается на UDP через socks: раньше туннель поднимался,
  но имена не резолвились и «ничего не грузилось»
- у входа socks задан `ip` — без него клиент не знает, куда слать датаграммы
  после UDP ASSOCIATE
- запросы AAAA отключены: TUN поднят только для IPv4, и попытки идти по IPv6
  подвешивали часть сайтов
- исключение приложения из туннеля больше не проглатывается: если оно не
  применилось, подключение прерывается с ошибкой, а не уходит в петлю
- после подключения приложение само проверяет канал через локальный вход ядра
  и показывает результат на экране


**2.0.1**
- ядро отказывалось читать конфигурацию: правило маршрутизации `geoip:private`
  требует файла `geoip.dat`, которого в APK нет. Частные подсети перечислены
  явным списком, а конфигурация теперь проверяется тестом на настоящем парсере
  Xray (`core/parse_test.go`)


**2.0.0**
- собственный туннель внутри приложения: ядро Xray и tun2socks встроены в APK,
  v2rayNG и другие клиенты больше не нужны
- кнопка стала переключателем «Подключиться / Отключиться», состояние
  приходит из сервиса, в шторке висит уведомление с отключением
- сборка разделена по архитектурам


**1.2.0**
- если совместимого клиента нет, приложение открывает страницу подключения
  на сервере со списком приложений (Happ, v2rayNG, Hiddify, Streisand, V2Box)
  вместо ухода в Google Play


**1.1.0**
- выбор локации прямо в приложении: список приходит с сервера, ключ
  перевыпускается на выбранной ноде без переустановки
- иконка и логотип TargetVPN
- исправлено подключение: на Android 11+ система скрывает чужие приложения,
  поэтому `resolveActivity` отвечал «клиента нет» даже когда v2rayNG стоял, и
  приложение уводило в Google Play. Теперь в манифесте объявлен запрос на схему
  `vless://`, ключ отдаётся напрямую, а магазин предлагается только в диалоге,
  если клиента действительно нет

**1.0.0** — привязка по HWID, статус подписки, выдача ключа.
